# Analysis Rules

## Current status

No analysis rules are implemented in Phase 1. The URL analyzer, email analyzer, and risk engine modules are placeholders so that later phases have clear extension points.

## Planned URL rule families

Future URL analysis will inspect the submitted value locally for scheme, IP hostname usage, URL and hostname length, subdomain depth, TLD context, suspicious keywords, `@` notation, unusual ports, shortening services, encoding, suspicious characters, path depth, domain structure, and punycode/IDN indicators.

## Planned email rule families

Future email analysis will inspect sender details, sender-domain context, Reply-To relationships, subject and body language, urgency, threats, account suspension language, credential and financial requests, verification requests, extracted URL strings, and attachment names or extensions.

## Scoring policy to be added later

A later phase will define versioned, deterministic weights, category caps, duplicate suppression, score bands, verdict language, explanations, and recommendations. No scores or verdicts are generated by the current foundation.

## Safety requirement

The URL rules must analyze strings only. They must not resolve DNS, issue HTTP requests, follow redirects, crawl pages, or invoke third-party reputation services.
