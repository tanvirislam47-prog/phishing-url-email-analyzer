About the project

Useful context for
uncertain moments.

This project is an educational analysis aid for recognizing suspicious characteristics in URLs and emails. It is designed to make its reasoning visible.

01 / Purpose

Heuristics, not a verdict machine.

Phishing often relies on familiar patterns: urgency, identity mismatches, concealed destinations, and requests for sensitive information. This application is designed to surface those patterns in a way that a person can review and question.

The local analysis engines preserve evidence, an explanation, and a practical recommendation for each indicator. The goal is to improve judgment—not to replace it.

02 / How it works

A local analysis boundary.

URL submissions are inspected as strings. Email submissions are evaluated through their sender details, message text, extracted URL strings, and attachment names. No submitted URL will be opened, crawled, resolved, or requested by the application.

01
Structural analysis

Inspect notation, length, host structure, encoding, ports, and other local characteristics.

02
Social-engineering analysis

Identify language and context associated with urgency, threats, credential requests, and financial pressure.

03
Explainable scoring

Combine independent indicators into a bounded score while retaining the reasons behind it.

03 / Technology

Built to stay understandable.

A small Django monolith keeps the project easy to run, inspect, and extend for a university or portfolio demonstration.

01Python + Django

Server-rendered forms, views, and templates.

02SQLite + ORM

Local persistence with readable database queries.

03HTML + CSS + JS

Responsive interface with minimal client-side code.

04 / Limitations

What this tool cannot promise.

The application is an analysis aid. It cannot guarantee that a message or URL is safe, and it cannot prove maliciousness using local heuristics alone. A legitimate message may contain unusual language, while a carefully crafted phishing message may avoid obvious signals.

Independent verification remains important. If a message requests credentials, payment, or urgent action, contact the organization through a known, trusted channel instead of using the message’s links or reply path.

◈

Design principle

Make the boundary visible. Make the reasoning reviewable. Make the next action safer.
